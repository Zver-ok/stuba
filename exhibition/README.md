# KazAgroFarm — запись на встречу и кабинет

Самостоятельный PHP-сайт, не шаблон WordPress. Основной сайт тракторов не затронут. Даты и адрес взяты с приглашения: 21–23 октября, стенд C6, МВЦ EXPO, Мангилик Ел, 53/1, Астана. Год мероприятия в приглашении не указан — в тексте даты он не добавлен.

## Что работает

- Компактный адаптивный лендинг: картинка сверху, форма под ней, маршрут в 2ГИС, телефон и кнопка WhatsApp. В форме: имя, фамилия, телефон Казахстана, физлицо/юрлицо, обязательное название компании для юрлица, необязательное направление интереса и согласие.
- Серверная проверка и сохранение в SQLite или MySQL / MariaDB. Один номер телефона — одна регистрация. Повторная отправка не создаёт дубликат.
- Подтверждение записи после фактического сохранения, отображение ошибок, защита от повторного клика и простого спама.
- Отдельный кабинет `admin.php`: пароль, общая статистика, динамика за 7/30/90 дней, точные значения по дням, список заявок с пагинацией, статусы, CSV за выбранный период.
- Учёт UTM: source/medium/campaign в заявке и сводка источников.
- Сессии, CSRF, параметризованные запросы, экранирование вывода, защита CSV от формул, ограничение попыток входа и отправки. Данные и хеш пароля находятся вне публичной папки.

## Размещение на хостинге

Нужен PHP 8.1+ (рекомендуется 8.3/8.4), HTTPS и доступ к записи в приватную папку. Для SQLite включите `PDO` и `pdo_sqlite`; для MySQL / MariaDB — `PDO` и `pdo_mysql`. Менять версию MySQL только ради этого сайта обычно не требуется: поддерживается MySQL 5.7+ / MariaDB 10.3+. Автоматическое переключение существующих данных между базами не выполняется.

Структура:

```
exhibition/
  public/          ← корень сайта / document root
    index.php
    api.php
    admin.php
    setup.php       ← одноразовая установка через браузер
    privacy.php
    assets/
  app/             ← вне document root
    bootstrap.php
    create-admin.php
  private/         ← вне document root, доступна PHP для записи
  tests/
```

Загрузите папку целиком и назначьте **`exhibition/public` корнем отдельного сайта/поддомена**, например expo.your-domain.kz. Не назначайте корнем всю `exhibition`: это может открыть приватные файлы, особенно на Nginx. При невозможности менять корень сайта попросите хостинг настроить размещение `app` и `private` вне публичной папки и соответствующий путь в `require`. `.htaccess` — дополнительная защита для Apache; Nginx их не читает.

Приватная папка должна принадлежать пользователю, под которым работает PHP; рекомендуемые права 0700. База и сессии создаются автоматически. Можно переопределить путь переменной окружения `EXHIBITION_DATA_DIR`, но он тоже должен оставаться вне document root. Не публикуйте `private`, не включайте её содержимое в Git; делайте защищённые резервные копии базы. С отключённым кешированием страниц регистрация и аналитика работают корректно: исключите весь сайт из HTML-кеша/CDN-кеша, особенно `index.php`, `api.php`, `admin.php`.

### Hostia: form.atm.hhos.net без изменения папки поддомена

Если поддомен уже указывает на `domains/atm.hhos.net/public_html/form`, используйте такое размещение:

```
domains/atm.hhos.net/
├── public_html/
│   └── form/                 ← содержимое exhibition/public из архива
│       ├── index.php
│       ├── api.php
│       ├── admin.php
│       ├── setup.php
│       ├── privacy.php
│       ├── bootstrap-loader.php
│       ├── .htaccess
│       └── assets/
└── exhibition/               ← создайте рядом с public_html, не внутри неё
    ├── app/                  ← папка exhibition/app из архива целиком
    └── private/              ← папка exhibition/private из архива целиком
```

Публичные PHP-файлы сами находят серверную часть по этому пути. Редактировать require не нужно. В файловом менеджере поднимитесь из `form` два уровня до `domains/atm.hhos.net`, создайте там `exhibition` и поместите в неё `app` и `private`. Код установки создайте в `domains/atm.hhos.net/exhibition/private/setup-key.php`. Откройте **https://form.atm.hhos.net/setup.php**; кабинет — **https://form.atm.hhos.net/admin.php**. Нужны PHP 8.1+ и расширение выбранной базы; HTTPS включается в панели хостинга.

Если хостинг запрещает PHP доступ за пределы `public_html` через open_basedir, это ограничение нужно изменить в панели или через поддержку хостинга, разрешив `domains/atm.hhos.net/exhibition`. Не переносите базу в публичную папку в обход ограничения.

### Установка без терминала — через файловый менеджер

1. Разместите файлы по структуре выше. В панели хостинга включите PHP 8.1+ и подходящее PDO-расширение.
2. В папке **`exhibition/private`**, не в `public`, создайте файл **`setup-key.php`**:

```php
<?php
return 'ВАШ_СЕКРЕТНЫЙ_КОД';
```

Замените текст в кавычках на **свой случайный код из 24–200 латинских букв, цифр, дефисов или подчёркиваний**. Не используйте показанный текст или публичный пример как настоящий код. Пароль кабинета задаётся отдельно.

3. Откройте на своём домене **`/setup.php`**. Введите код из файла, придумайте логин и пароль кабинета (не менее 12 символов).
4. Выберите базу:
   - **SQLite**: база создастся сама в приватной папке, другие поля не нужны.
   - **MySQL / MariaDB**: сначала создайте отдельную пустую базу и пользователя через панель хостинга, затем введите хост, порт, имя базы, имя пользователя и пароль базы. Данные берите из панели; `localhost` подходит не всем хостингам. Таблицы создадутся автоматически; пользователь должен иметь права создавать таблицы и читать/изменять данные. Не используйте базу WordPress: имена таблиц `visitors`, `leads`, `login_attempts`, `submit_attempts` зарезервированы для этого приложения.
5. После сообщения **«Кабинет настроен»** войдите на **`/admin.php`** с созданными данными.

Установщик проверяет подключение до создания администратора. Код установки сравнивается на сервере, есть CSRF и ограничение попыток. Файл `setup-key.php` удаляется после успеха; наличие `private/admin.json` блокирует повторную установку. Можно дополнительно удалить `public/setup.php` и `public/assets/setup.js` после настройки. Логин/хеш пароля сохраняются в `private/admin.json`, настройки базы — в `private/database.php`. **Не удаляйте admin.json**, иначе блокировка установки исчезнет. Копии файлов с расширениями `.bak`, `.txt` и т. п. не оставляйте в публичной папке.

Пароля по умолчанию нет. Для смены пароля без терминала создайте новый `admin.json` локально CLI-командой ниже и замените его через защищённый файловый менеджер. Публичного сброса пароля без проверки владельца нет.

### Дополнительный вариант — терминал

Из папки `exhibition`:

```bash
read -rsp 'Новый пароль (не менее 12 символов): ' admin_password; echo
printf '%s\n' "$admin_password" | php app/create-admin.php admin
unset admin_password
```

Команда создаёт/обновляет доступ администратора; существующие сессии аннулируются. Данные подключения MySQL эта команда не задаёт — их устанавливайте через `setup.php` до создания администратора либо подготовьте приватный `database.php` локально.

## Изображения и настройки

Баннер пока **иллюстрация-заглушка** `public/assets/registration-banner.svg`. Для замены просто загрузите свой файл **`banner.jpg`**, **`banner.png`** или **`banner.webp`** в `public/assets` (на Hostia: `public_html/form/assets`). Страница автоматически выберет его вместо SVG. Если загружены несколько вариантов, приоритет — JPG, PNG, WebP. Используйте отдельный баннер без нарисованных полей формы: настоящая HTML-форма располагается под изображением. Картинка отображается целиком, без обрезки; текст приглашения и логотипы можно включить в сам баннер. Логотипы в заглушке приблизительные.

Маршрут ведёт на **https://go.2gis.com/TC3u8**, включая кнопку в подтверждении записи. Телефон под формой: **+7 777 555 06 65**, рядом — WhatsApp.

При обновлении этого дизайна достаточно заменить файлы из `public`. **Папки app и private не переустанавливайте; базу и пароль не удаляйте.** CSS/JS подключены с параметром версии, чтобы браузер подхватил новый вид.

Дата, адрес, стенд, контактный телефон — константы в `app/bootstrap.php`. Сейчас используются контакты из предыдущего сайта, проверьте их. Текст политики находится в `public/privacy.php`: перед запуском укажите фактическое юрлицо-оператора, его контакт и конкретный срок хранения данных. Запись на стенд не является входным билетом на выставку.

## Статистика

- **Посетители**: уникальные браузеры по случайной cookie (90 дней), не точное количество физических людей.
- **Просмотры**: повторные открытия лендинга также учитываются; админка и служебные URL не учитываются.
- **Начали форму**: первый ввод пользователя за день (событие JS). Показатель за период суммирует такие дни.
- **Регистрации**: реально сохранённые уникальные по телефону заявки; дубли не увеличивают счётчик.
- **Конверсия**: регистрации / уникальные посетители за соответствующий период.
- По дням один браузер учитывается каждый день, общий счётчик — один раз за период. Поэтому сумма ежедневных посетителей может превышать общий счётчик.
- Время: **Asia/Qyzylorda, UTC+5**. Известные боты исключены по User-Agent; блокировка cookie, сканеры и смена браузера ограничивают точность. Персональные данные в отчётах доступны только администратору.

Ссылка для таргета:

```
https://your-domain.kz/?utm_source=instagram&utm_medium=paid&utm_campaign=kazagrofarm
```

Последние непустые UTM текущей сессии сохраняются в заявке. Meta Pixel не установлен: внутреннюю статистику сайт собирает сам. В JS предусмотрено событие `exhibition:registered` с флагом duplicate для дальнейшего подключения рекламной аналитики; персональные данные в него не передаются.

## Локальный запуск

Обычный PHP с SQLite:

```bash
php -S 127.0.0.1:8002 -t public
```

В текущей облачной среде PHP и SQLite установлены локально:

```bash
/workspace/.stuba-runtime/bin/php-sqlite -S 127.0.0.1:8002 -t /workspace/stuba/exhibition/public
```

Если собираете среду заново: получите официальные Debian-пакеты `php8.4-cli`, `php8.4-common`, `libargon2-1`, `php8.4-sqlite3` с проверкой APT, распакуйте в локальный runtime и включите расширения `pdo.so` и `pdo_sqlite.so`, либо установите PHP/PDO SQLite обычным способом на хостинге.

## Проверка

Нужны Node.js, Playwright и Chromium. Изолированная проверка создаёт временную базу и тестового администратора, затем удаляет их. Не запускайте её против рабочего сайта.

```bash
PHP_BIN=/workspace/.stuba-runtime/bin/php-sqlite tests/run-smoke.sh
```

Для дополнительной проверки установки через браузер:

```bash
TEST_WEB_SETUP=1 PHP_BIN=/workspace/.stuba-runtime/bin/php-sqlite tests/run-smoke.sh
```

Проверяет секретный код установки, несовпадающие пароли, блокировку повторной установки, реальное сохранение, обязательную компанию для юрлиц, CSRF, отсутствие дублей, UTM, начало формы, вход в кабинет, статусы, безопасный CSV, недоступность приватных файлов и мобильную ширину 320/390 px. Проверенные тестовые данные не входят в комплект для публикации.

MySQL-путь дополнительно проверен на локальной MariaDB 11.8: установщик, сохранение заявки, дубли, UTM, авторизация кабинета, статусы и CSV. Тесты MySQL требуют отдельного изолированного сервера/базы `exhibition_test`; не используйте рабочую базу для тестирования.

Размещение Hostia дополнительно проверяется командой `TEST_LAYOUT=hostia TEST_WEB_SETUP=1 PHP_BIN=/workspace/.stuba-runtime/bin/php-sqlite tests/run-smoke.sh`: app и private действительно расположены вне public_html, переменная EXHIBITION_DATA_DIR не используется.
